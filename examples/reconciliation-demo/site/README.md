# Interactive reconciliation example

Static, browser-only presentation of the existing seven-file synthetic package.
The original is retained before the visitor changes amounts. Presets and custom
amounts modify actual canonical JSON strings; Check computes SHA-256 fingerprints
with Web Crypto at click time. It does not return stored PASS/FAIL results.

The visitor can inspect the original and candidate files, see field changes,
compare full file fingerprints, and inspect the retained commitment. Controls
never update that commitment. Refresh restores the fixture. Nothing is uploaded
or persisted. Do not add confidential data to the fixture: it is shipped to every
visitor, including its blinding nonce.

## Relationship to the independent verifier

`npm run build:reconciliation-site` regenerates the canonical serializer and bounded
integer arithmetic from the existing functions without changing them. Browser
SHA-256 uses the same domain-separated commitment framing. The fixture contains
an actual original package, manifest and anchor generated by the Node demo.

`checker.mjs` is a narrow comparison implementation for this fixed synthetic
workflow, **not the general evidence-envelope verifier**. It validates the pinned
manifest commitment/context, fixed adapter and full specification, all seven file
hashes, the six-file simulated approval reference, and the arithmetic. It does
not issue or verify a historical execution receipt or assert trusted chronology.
Use `scripts/reconciliation-demo.js check` or the core canonical-wire verifier for
independent verification. Automated tests run the same candidate bytes through
both implementations and compare the results.

The reference is included in the same app as the candidate. This demonstrates a
custody boundary; it does not enforce it against the site operator. A replacement
site can supply a replacement anchor. A real reviewer must independently retain
the original expected commitment, context and trusted verifier. A PASS does not
establish balanced accounts, real approval, true data, historical execution,
trusted timing, absence of other runs, or compliance.

## Preview and export

Serve `dist/` over HTTP, e.g. `python3 -m http.server 8766 --directory dist`.
There are no runtime dependencies, third-party scripts or build framework.
Modern browsers need Web Crypto, JavaScript modules and `String.isWellFormed`.

From the repository root, make an attachable, self-contained version:

```sh
node scripts/build-reconciliation-site.js --standalone /tmp/reconciliation-demo.html
npm run test:conformity
npm test
```

The export embeds the same scripts, styles and fixture, requires no network
requests, and runs in a modern browser when opened as a local HTML file.

An optional WebMCP tool invokes the same preset/check actions when supported.
No supported WebMCP validation context was available; that optional integration
has not been verified in a WebMCP-enabled browser. The visible controls do not
depend on it. Browser visual/interaction QA was not requested or performed.
